**Cordon 0.6.0**

> Breaking change: a command must now be covered by the policy to run.

Cordon is a Crystal shard that runs shell commands inside a platform-native sandbox with a configurable access policy. It works on macOS (via `sandbox-exec` / Seatbelt) and Linux (via `bwrap` / Bubblewrap), presenting both as a single clean API.

**Changes**

* **The policy is the whole perimeter** - Cordon previously granted the command it was asked to run access to its own binary, even when the policy granted nothing else. That exception is gone. Naming a binary is not authority to run it — under the case Cordon is built for, where a user sets the perimeter and an agent chooses the commands, the command is exactly what the untrusted side controls. Grant the command's location like any other path, via `read_only`, `Preset::System`, or a toolchain preset.
* **Relaunch grants less** - `Cordon.relaunch` still grants the running executable access to itself, but the executable only, no longer its containing directory. Since read access implies execution, the old form quietly made every neighbouring binary runnable inside the cordon. A self-relaunching binary's other dependencies are the caller's to grant; see the README.
* **Profiles no longer depend on the command** - `SandboxExec#generate_profile` takes only a policy again, so `cordon inspect` now previews exactly what will be enforced.
